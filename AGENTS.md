# AGENTS.md -- Instructions for AI Coding Agents

Instructions for Claude Code and similar AI coding agents working on the
Kaplos codebase. Read this entire file before making any changes. "Code is
liability" (below) takes precedence over every other instruction here.

This file is the agent's read-fully contract: it states only what the agent
must internalize at each anchor. `AI-WORKFLOW.md` holds the loop rules,
`AI-ORCHESTRATION.md` explains why each rule exists, and `docs/DECISIONS.md`
records the ratified decisions.

## Code is liability (operational rule)

First rule, because every other rule degrades if it is not followed.
General-purpose models bias toward producing more code; in a codec that bias
is decoder cost, audit cost, and a candidate source of encoder/decoder
mismatch. Counter-measures, on every task:

1. **Inline before extracting.** No helper, class, wrapper, or layer unless
   at least two existing call sites benefit. One hypothetical future caller
   is not a justification.
2. **Reuse what is there.** The standard library and numpy come first. Do not
   add a dependency that duplicates either.
3. **Prefer deletion to addition.** If a removal also resolves the issue, take
   it. A change that removes more than it adds is the default shape.
4. **Stop and report instead of expanding scope.** A correct but out-of-scope
   improvement is reported as a follow-up candidate, never implemented in
   passing.
5. **Justify additions.** When code must be added, the commit message states
   which alternatives were rejected and why. "It seemed cleaner" is not one.
6. **Resist abstraction for its own sake.** Three similar lines beat a
   premature helper; the codebase is small enough that duplication is
   auditable.

## Project overview

Kaplos is an audio codec for fixed-size 1 ms packets: 48 samples per channel
at 48 kHz, every packet exactly the configured size, no algorithmic delay
beyond collecting the packet, and lossless whenever the packet budget allows.
Its target is microcontroller-class hardware. This repository holds the
reference implementation in Python (numpy and numba), the measurement
harness, and the experiments behind every published figure.

## Execution profile

Instruction files carry an "Execution profile" -- a recommended model class
and reasoning depth for the executing session.

- The profile addresses the operator's launch choice. You do not select,
  change, or re-grade it. If you are running, the operator has chosen.
- The profile never modifies the contract. Gates, byte-exact before-snippets,
  out-of-scope lists, and stop-and-report apply identically under every
  profile. "deep" is not a license for initiative; "none" is not an excuse
  for a failed gate.
- Escalate instead of grinding. If execution repeatedly trips gates, or needs
  live debugging beyond applying the written edits, STOP and report that the
  task appears to exceed the profile. A stop-and-escalate is a correct
  outcome; a forced pass is not.
- An instruction with no profile: ask the operator before starting.

## Hard invariants -- never violate these

1. **The decoder is integer and deterministic.** Every value the decoder
   computes -- prediction, adaptation, reconstruction, entropy decoding -- is
   integer arithmetic, and the encoder updates its copy of the decoder state
   through the same code. Floating point is allowed only in encoder-only
   analysis whose result the decoder never recomputes (noise shaping, rate
   control). A decoder output that differs from the encoder's reconstruction
   in a single sample is a defect.
2. **Every capped packet has exactly the configured size.** A packet that
   cannot fit is coded in the escape mode. A capped mode never emits a
   shorter or a longer packet.
3. **Lossless means bit-exact.** Step index 0 reproduces the input samples
   exactly, through the real bitstream.
4. **No look-ahead beyond the current packet.** The codec adds no algorithmic
   delay beyond collecting the packet's 48 samples per channel.
5. **No third-party audio, no confidential material.** The repository holds
   no excerpt of a commercial recording or test CD, no file encoded from one,
   and nothing received under a non-disclosure agreement (D3, D4). Test
   signals are synthetic and generated by code.
6. **No new dependencies without justification.** The runtime set is the
   standard library, numpy, numba and soundfile; tests use `unittest`.

## Stop and ask the operator

Some changes are decisions, not edits. For these, STOP, present the change,
and wait for explicit approval:

- **Any bitstream change:** packet header, step table, Rice coding
  parameters, escape mode, stereo modes, key packets.
- **Any change to the decoder arithmetic:** predictor stages, normalisation,
  rounding, clipping, adaptation constants.
- **Any change to a measurement definition:** the NMR heuristic, the
  synthetic signals, the baseline settings. Published figures stay
  comparable only while these stay fixed.
- **A new dependency, a new top-level directory, or anything that contradicts
  a ratified decision** in `docs/DECISIONS.md`.

## Code style

- **ASCII only.** All code, comments, messages, docs, and commit messages are
  printable ASCII. Use `--` not an em dash, `->` not an arrow, `"` not curly
  quotes, "and" not an ampersand. Enforced by `tests/test_ascii.py`, which
  checks every file git tracks or would track and exempts only the verbatim
  licence texts under `LICENSES/`.
- **US English** in code and documentation.
- PEP 8, four-space indentation, lines up to 110 characters.
- **Every source file starts with an SPDX header** (D2):
  `# SPDX-License-Identifier: BSD-2-Clause-Patent` for code,
  `<!-- SPDX-License-Identifier: CC-BY-4.0 -->` for documentation. Two
  exceptions carry no header and fall under D2 by file type: files whose
  format fixes the first line (YAML frontmatter of roadmap items and skill
  files), and the vendored `roadmap-items` skill, which stays byte-identical
  to its upstream.
- **Comments are self-contained:** no roadmap ids, instruction references,
  historical narrative, or chat-only labels. The one durable cross-reference
  a comment may carry is a decision number from `docs/DECISIONS.md`.

## Testing

- `unittest` only; tests pass with `python3 -m unittest discover -s tests`.
- Hermetic: no network, no audio file from outside the repository. Signals
  are generated at test time; temporary files go to `tempfile` directories.
- Test both success and error paths; no assertion-free tests.
- The hard invariants are tested through the real bitstream: lossless round
  trip, exact packet size, decoder output equal to the encoder's
  reconstruction.

## Package layout

Fixed by D5:

- `kaplos/` -- the codec: predictor, quantiser, Rice coding, packet encoder
  and decoder, encoder-only noise shaping, the command-line tool.
- `harness/` -- the NMR heuristic, the synthetic signal generator, the
  baseline codecs, and the Opus Custom helper program.
- `experiments/` -- one script per experiment stage; each prints the table it
  measures.
- `tests/` -- the unit tests.
- `docs/`, `roadmap/`, `.claude/skills/roadmap-items/`, `LICENSES/`.

Generated signals, decoded audio and measurement output go to `out/`, which
is never committed.

## Gates

The pre-commit gate, run exactly as written from the repository root inside
the dev container (D6):

```sh
python3 -m unittest discover -s tests -v
```

It must succeed. A green gate is the only acceptable pre-commit state. The
dev container carries the tool set D6 defines; report a tool you need and do
not find to the operator, never install or fetch one.

## Measurements

An instruction that delegates a measurement runs it in a throwaway worktree,
commits nothing, and reports the verbatim output together with the exact
command that produced it. Every case the measuring program sets aside is
listed in the report, not folded into a default.

## What not to do

- Do not improvise when a before-snippet does not match the tree. A
  whitespace-only difference on a line you are deleting is immaterial: delete
  it and note the divergence. Any other mismatch means the tree has drifted
  -- stop and report.
- Do not alter retained code to satisfy a literal acceptance grep. If a grep
  for a removed symbol still matches because the token legitimately survives
  in a kept path, the criterion is flawed -- report it and leave the code
  alone.
- Do not establish a file's contents through an arbitrary line window
  (`sed -n 'A,Bp'`, `head`, `tail`). An existence or absence claim rests on a
  whole-file search or a full read, never on a slice. A window is legitimate
  only after a search has located the target -- prefer `grep -n -C3 PATTERN
  file`.
- Do not change a function signature or remove a symbol without searching the
  whole repository -- `kaplos/`, `harness/`, `experiments/`, `tests/` -- for
  callers. Fix every caller in the same step.
- Do not commit anything under `out/`, and no audio file of any kind.

## Commit messages

Conventional Commits. Format `<type>(<scope>): <description>`: first line
imperative, at most 72 characters, no period. Types: `feat fix refactor perf
test doc docs style chore build ci revert`. Breaking changes add `!` after
type or scope and explain in the body.

**AI attribution.** A commit produced with an AI model MUST end with one
`Co-Authored-By:` trailer per model, naming the model
(`Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`). It MUST NOT
disclose any other detail of the AI interaction: no session links or ids
(e.g. a `Claude-Session:` trailer), no prompts, transcripts, or tool
metadata. Delete such a line when the tooling adds one. Why: the history is
public and permanent.

## When a gate fails: diagnose, never assign blame

A failing check is a signal to diagnose, not a verdict to defend against.

1. **Blame is irrelevant; spend zero reasoning on it.** The failure is part of
   the working state you own; it gets diagnosed.
2. **Never locate the cause outside the work.** Three forbidden stopping
   points: the environment; other commits ("pre-existing" is a still-open
   defect you now own); an unexpected in-tree file (the file is part of the
   contract; your model was incomplete).
3. **Diagnose in a fixed order:** re-read the relevant spec or decision;
   re-read the existing code the failure touches; re-read your own change.
4. **Never shrink the gate to make it pass.** No test selector, `skipTest`,
   loosened tolerance, pipe to `true`, or swallowed exit code. If the full
   gate cannot pass, that is the finding to report.

## Completion report

Every run ends with a report whose last two sections are mandatory:

- **Observations** -- the verbatim output of every acceptance observation the
  instruction names. Not a paraphrase, not "as expected".
- **Follow-up candidates** -- every correct-but-out-of-scope improvement
  encountered, each with its file and one line of what and why; or the single
  word `none`.

A missing section is a gate failure.
